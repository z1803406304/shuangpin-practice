**核心交互（严格对齐截图）**
- 不依赖 `<input>` 焦点：全局 `keydown` 捕获，`e.code`（`KeyQ`…）判定，兼容任意键盘布局；`e.isComposing` 过滤输入法候选态。
- 逐键即时判定：第 1 键=声母键，第 2 键=韵母键。错键立刻标红 ✗ 并把该键记入错误统计；正确显示 ✓ 并按配置延时（默认 120ms）自动下一题。
- 快捷键：`空格`/`回车` = 清空或切换下一题；`Tab` = 显示答案（多音字可能不唯一）；`Backspace` = 删一键。
- 纠错语义（可配置）：**严格**（错键即判错、必须重打本题）/ **宽松**（错键标红但允许继续打完）。
- 全程无需鼠标，键盘 100% 可操作。

### 3.1 键位表（已按截图逐键核对）

| 键 | 声母 | 韵母 | 键 | 声母 | 韵母 | 键 | 声母 | 韵母 |

### 3.2 编码规则
1. 有韵母键的韵母直接查表；`zh/ch/sh` 走 `V/I/U`。
2. **y / w 视作普通声母**：`yao → y+c`、`yong → y+s`、`wang → w+l`、`wo → w+o`、`yi → y+i`。
3. **零声母（无 y/w）**：`a→aa`、`e→ee`、`o→oo`；`ai/an/ao/ei/en/er/ou` 用全拼本身；`ang→ah`、`eng→eg`。
4. ü 系：`lü→lv`、`nüe→nt`（V 键亦有 ü 标注，按「V=ü 单韵母、T=üe」处理）。
5. `ong / iong` 同键 S，`ui` 在 V，`un` 在 Y，`in` 在 B，`ing` 在 K，`uai` 在 K，`ia/ua` 同在 X。

### 3.3 音节目录（约 410 个）
用**生成脚本**从 `pinyin-pro` 字典遍历 CJK 基本区 + 扩展 A，抽取无调音节去重，再与已知 410 音节量级交叉校验，避免手抄错漏；音节按字频加权排序（供「全部拼音组合」模式按常用度出题，而不是纯均匀随机）。

## 4. 数据层

### 4.1 题库模式（用户已选全部 6 种）
| # | 模式 | 说明 |
| --- | --- | --- |
| 1 | 全部拼音组合 | 音节表随机（可切「均匀随机 / 字频加权」）；题面显示音节 + 代表字 |
| 2 | 常用汉字 | 按字频排序，可选范围 Top 500 / 1000 / 3500；题面 汉字 + 拼音 |
| 3 | 词组 | 常用词语库，逐字推进 |
| 4 | 句子 / 短文 | 整句显示、当前字高亮，逐字推进并统计整段成绩 |
| 5 | 自定义文本 | 粘贴任意文本 → 生成题组；文本可命名保存、可导入导出 |
| 6 | 键位记忆训练 | 只练「韵母 → 按键」映射：给韵母选键 / 给键选韵母 / 键位图找位置，含声母专项 |

> 通用能力：错题本（只练错过的字/键，v1.1）、题量/时长目标、范围过滤（只练某几类韵母）。

### 4.2 数据文件
```
src/data/
  syllables.json    # [音节, 代表字, 权重]
  hanzi.json        # 常用汉字（按频率，含拼音）
  words.json        # 常用词组（约 500 条，人工 curated）
  sentences.json    # 句子/短文（约 80 条，含标点处理规则）
  xiaohe.json       # 键位表 + 零声母表（单一数据源，UI 与编码器共用）
```
`xiaohe.json` 同时驱动**编码器**和**键位图渲染** → 改表不可能出现「图与判定不一致」。

### 4.3 字频数据来源（已落地）
**实际采用**：`ruddfawcett/hanziDB.csv`（Jun Da《Modern Chinese Character Frequency List》，
9901 字，按频率排名）。由 `scripts/fetch-flypy-table.mjs` / `scripts/sources.mjs` 在生成期下载到
`data-src/`（已 gitignore，可重下），产物 `src/data/syllables.ts` 与 `src/data/hanzi.ts`
**进仓库，运行时不联网**。

两个用途：
1. **题面代表字**：每个音节取该音节下字频最靠前的汉字（不会再出现「㳘」这种生僻题面）。
2. **音节常用度权重**：按 Zipf 近似，字频 ≈ 1/排名，所以音节常用度 ≈ Σ(1/排名)，
   再做 0.4 次幂压缩归一化到 1~100 → 「常用优先」出题（的=100、一=83、是=74、…、欻=3）。

- 键位图高亮 = 从 `judge.ts` 状态派生，与判定共用同一份键位数据。

## 8. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 中文输入法抢按键 | 提示切英文输入法（截图同款说明）；`e.isComposing` 过滤；主要操作同时支持鼠标点击键位图 |
| 键盘布局差异（Dvorak 等） | 用 `e.code` 而非 `e.key` |

| 数据来源失效 | §4.3 三级降级，最终产物进仓库，运行时不联网 |
| npm 缓存沙箱问题 | `.npmrc` 固定 `cache=.npm-cache`（已实测） |

### 10.3 规划阶段纠正的三个错误
以下三个问题由测试直接发现（这也是 M1 必须先做全量回归的原因）：
1. `zh/ch/sh` 的输入槽字母显示成了 `zh/ch/sh`，应为 `v/i/u`（键帽字母）。
2. `normalizeSyllable` 先做 NFD 分解再替换 ü，导致大写 `Ü` 和 `ü` 认不出来（顺序必须反过来）。
3. 测试里的期望值把 **也** 写成 `yp`、**王** 写成 `wl`，官方码表证明正确值是 `ye` 和 `wh`。
   没有码表交叉验证，这类期望值错误会直接变成产品 bug。

| 历史记录 | 汇总（轮数/累计题数/累计时长/平均与最好速度/平均正确率）+ **速度曲线**（SVG 折线）+ 记录表（可单条删除）+ 导出 JSON + 两步确认清空 | `components/HistoryPanel.vue`、`components/Sparkline.vue` |
| 统计层扩展 | 新增 `charErrors`（错误归属到字）与 `keyTimes`（每键反应时间），并区分「手滑按错」和「没记住键位」 | `core/stats.ts` |
| 记录持久化 | 纯逻辑（构建/汇总/序列化/校验）与 localStorage 落地分离 | `core/history.ts`、`stores/history.ts` |

### 11.2 两个设计决策
1. **一轮练习 = 一条记录**。不采用「每完成一题追加一条」，而是把当前轮次作为一个
   「进行中快照」反复覆盖写入 `shuangpin.active.v1`（每题完成时、切标签页/关页面时各写一次）；
   下次打开时 `initHistory()` 会把没结算的那轮自动补进历史。
   这样既不会丢数据，也不会因为刷新/切页把一轮练习切成一堆碎记录。
2. **区分「按错」和「想得慢」**。`keyErrors` 记错误次数、`keyTimes` 记每键反应时间：
   前者高说明手滑或记混，后者高说明键位没记牢。两种问题的练法完全不同，
   所以结算面板分成两栏而不是合成一个「错误排行」。
   反应时间超过 3 秒按 3 秒计（发呆不算），新题面的第一击从**题面显示**那一刻开始计时。

## 12. 实施记录（卡住自动提示）

### 12.1 需求与取舍
「一个字长时间打不出来，就提示键位」。确认后的策略：
- **只闪键位、不自动给答案**（默认）：在键位图上闪烁「该按的那个键」，帮回忆但不剥夺思考
- 触发时间 **3 秒**；一旦击键就重新计时
- 提示过的题**不计入独立正确率**，单独统计「依赖提示」

另外把「再久一点直接显示答案」做成了**可选项**（默认关闭，可选 6/10/15 秒），
因为那段逻辑和弱提示共用同一套阈值机制，加进去几乎不增加复杂度，但用户想要升级时不用改代码。
数值全部可调，收在新增的「更多设置」面板里（顺带把 M3 的数值设置项一起做了）。

### 12.2 设计：策略与定时器分离
`core/hint.ts` 是纯函数：把「等了多久」映射成「提示到第几级」。
- `stageForIdle(idleMs, policy)` → 0 / 1 / 2
- `nextStageDelay(idleMs, policy)` → 距下一次升级还差多少毫秒（到顶返回 null）
- `hintProgress(idleMs, policy)` → 等待进度 0~1（给进度条）

会话层只负责按 `nextStageDelay()` 排 tick 并在击键时重置计时。这样
「3 秒是否触发」「关掉后是否永远不提示」「答案阈值配得比弱提示还早怎么办」
这些边界全都能用单测覆盖，而不是靠人眼盯着秒表点。UI 侧的等待进度条也读同一个
`idleMs`，所以进度条和实际触发时刻不会各算各的。

### 12.3 成绩口径
`independent`（完全独立）/ `hinted`（依赖提示）两个计数互斥，
`independentRate = independent / done` 才是「独立正确率」；速度照常按打对的题数算
（提示会自然拖慢速度，不需要额外惩罚）；按键正确率不受提示影响。
结算面板里给出一行拆分：`完成 N 题：完全独立 X · 依赖提示 Y · 有错但没用提示 Z`。

### 12.4 测试
`npm test` 从 26 个增加到 **36 个**，新增 `tests/hint.test.mjs`（8 个用例）与
`stats.test.mjs` 的两个提示口径用例，覆盖：关闭提示、只闪键位永不给答案、
两段式升级、`nextStageDelay` 用返回值推进时间必须正好落在阈值上、
答案阈值比弱提示更早、两阈值相同、只开答案不开弱提示、进度条计算。

### 12.5 端到端验证结果（浏览器实测）
- 2.5 秒：`stage=0`、无闪烁、进度条 87%
- 3.4 秒：`stage=1`、**恰好 1 个键在闪，且正是该按的键**（`全/quan` → Q）、
  显示「⚑ 已提示」、进度条 100%、**没有出现任何答案**、ghost 槽位 0
- 7.4 秒：仍是 `stage=1`，仍然不给答案（验证「只闪键位」的承诺）
- 击键后：`stage=0`、`idleMs=0`、闪烁停止，`hintUsed` 保持为真（本题已被算作依赖提示）
- 完成本题：`hinted +1`、`independent +0`，统计条显示「0.0% 独立正确率 / 2 依赖提示（100.0%）」
- 按 `Tab`：`hintUsed` 变真（手动看答案同样算用过提示）
- 关掉自动提示后干等 4 秒：无闪烁、进度条也隐藏

- 「更多设置」面板：3 个下拉框显示的当前值正确（3 秒 / 不自动给答案 / 自动默认）、
  面板打开时按键不影响练习、`Esc` 可关
- 全程控制台零警告零报错

### 12.6 实现问题记录
1. **`complete()` 的位置参数改坏了**：为了加 `hinted` 把签名写成 `complete(failed, hinted, now)`，
   结果测试里 `complete(true, 1600)` 把时间戳当成了 `hinted`，语义整个错掉（4 个测试立刻红）。
   已改成显式对象参数 `complete(failed, { hinted, now })`。位置参数在布尔 + 时间戳这种组合上
   太容易传错，尤其是 .mjs 测试文件没有类型检查兜底。
2. **用 PowerShell 批量改测试文件把中文搞成了乱码**：`Get-Content/Set-Content` 往返时
   UTF-8 被按 GBK 解读，中文注释和字符串全部损坏（还把几行合并了）。
   已改用文件工具重写。教训：**这个环境里不要用 shell 命令改含非 ASCII 内容的文件**。
3. 期间还遇到一次「`hintStage` 自己退回 0」的假象，追查后确认是改完 `session.ts`/`stats.ts`
   后 Vite HMR 反复失效模块导致的（同一份脚本在页面刷新后稳定复现不出来，且打点显示
   定时器没有被重建）。**结论：验证行为要在页面刷新后、且没有并发改文件时做。**

### 13.1 M4：五种题库模式
| 模式 | 数据 | 说明 |
| --- | --- | --- |
| 常用汉字 | `hanzi.ts` 3500 字（按字频） | 可选前 300/500/1000/2000/3500；范围内均匀随机（范围本身就是频率筛选，再加权会让前 50 个字反复出现） |

| 自定义文本 | 用户粘贴，存 localStorage | 拼音在「添加」时转好并持久化；长文本按句末标点切成 4~12 字的小段 |
| 键位记忆训练 | 由键位表推导，无需数据 | 韵母→键 / 声母→键 / 音节→声母键 / 音节→韵母键，每题只按一个键 |

为了让「只按一个键」的题目能复用整套判定/统计/提示逻辑，做了两处重构：
1. `Encoded.codes` 从「固定两个键的元组」放宽成变长数组；判定状态机本来就按
   `codes.length` 判完成，所以单键题直接就能跑。
2. 题面模型从 `{字, 音节}` 升级成 `PromptPart`：`display / lead / tail / sub / note / syllable | codes`，
   于是单字、词、句、单键题可以共用同一个卡片组件（只是布局分成 `single` 和 `flow` 两种）。

### 13.2 拼音放在哪算：三种模式三种策略
取舍如下：

| 场景 | 方案 | 原因 |
| --- | --- | --- |
| 词组 / 句子 | **构建期**算好存进数据文件 | 多音字在「词」这一级用上下文判定更准（银行 = yin hang）；运行时不背 pinyin-pro 的 300KB |
| 自定义文本 | **动态 import** 按需加载，转好后持久化 | 任意文本没法预生成；只在用户点「添加文本」那一刻下载，首屏和日常练习不受影响 |
| 音节 / 汉字 / 键位训练 | 不需要 | 音节表里已经有音节，键位训练直接用键位表推导 |

结果：普通构建的主包 99KB gzip，pinyin-pro 被单独拆成 296KB 的懒加载 chunk。

### 13.4 M6：可双击的离线单文件包
`npm run build:offline` → `dist-offline/双拼练习-单文件版.html`（约 620KB，含内联的 pinyin-pro）。

做法：`vite build --mode offline`（IIFE 格式 + `inlineDynamicImports`）→ 再由
`scripts/inline-offline.mjs` 把 JS/CSS 塞进一个 HTML。

**这里遇到两个问题，都属于「静态检查全过、页面白屏」：**

1. **`String.replace` 的替换串里 `$` 有特殊含义**（`` $` ``、`$&`、`$'`、`$1`…）。
   Vue 的压缩代码里大量出现 `$attrs`、`$el`，用字符串替换内联时把 HTML 片段注入进了 JS，
   产物直接语法错误。改成**函数式替换**才正确。
2. **classic `<script>` 放在 `<head>` 里会立刻同步执行**，此时 `<div id="app">` 还没解析出来，
   `mount('#app')` 找不到目标时，Vue 只打一条警告、不抛异常，表现就是**白屏且没有报错**。
   module script 天生 defer 所以没这问题，但 `file://` 用不了 module。
   修法：把内联脚本插到 `</body>` 之前。

因此自检里加了两条硬约束，避免同类问题再次静默通过：
- 用 `new Function(js)` 真的去**解析**内联后的 JS（不是只查字符串特征）
- 断言 `<script>` 的位置在 `id="app"` **之后**

### 13.6 已修缺陷
1. **自定义文本丢字**：`pinyin(text, { type: 'array' })` 会给**标点也返回一项**，

2. **键位训练的声母分布失真**：`zh/ch/sh` 只占 20%（预期约 47%）。原因是「近期去重」会把

3. 常用汉字/键位训练的题型切换后不换题（设置改了但界面没反应）。修法：这两个设置的
   watcher 从「只 reset 出题器」改成「reset + 换题」。

### 13.7 「易错复习」模式

计划里把「错题本」列为 v1.1，但它决定练习闭环是否完整
（练完 → 结算看到易错字 → 只练这些字），实现成本不高，因此一并实现：

- 数据来源：历史记录里累计的 `charErrors` **合并本轮**刚按错的字，按错误次数加权抽样
- 字 → 音节映射不单独生成数据文件：现场从音节表代表字 / 常用字表 / 词组 / 句子
  四份数据源建表：这些正是题目可能出现的全部来源，覆盖率天然是 100%
- 空状态给明确提示（「还没有错题记录，先练几轮」），而不是给一道莫名其妙的题
- 题面会显示「这个字你按错过 N 次」，让复习有针对性

浏览器实测：故意按错 10 个字后切到该模式，连续 12 题全部命中错题池（含历史累计的
「后/反」和本轮的「了/描/照」），每题都带错误次数提示，零控制台报错。

1. **DOM 断言没等 Vue 渲染**：dispatch 完按键立刻读 `.stats` 拿到的是旧值，
   导致「键盘输入有反应」误报失败。这是本会话第三次踩同一个坑了，
   结论：**任何「操作 → 读 DOM」的验证都要留一个 tick**。
2. **把浏览器的临时 profile 建在了项目目录里**：无头浏览器会生成几万个文件，
   Vite 的 watcher 去 watch 这些文件直接把 dev server 搞崩（watch EBUSY 崩溃的第二次）。
   修法：临时 profile 放系统临时目录。

## 15. 历史记录导入

### 15.1 背景
之前只有「导出 JSON」，没有导入。备份是半个功能：换电脑、换浏览器、
误清空数据之后，导出的文件根本用不上。补上导入才算闭环。

### 15.2 设计：两步确认 + 幂等
- **两步确认**：选文件后不立刻写入，先显示「找到 N 条记录（时间范围）」，
  再让用户选 **合并导入** 或 **替换全部**。替换是破坏性的，所以按钮标红、
  并且在同一个确认行里，避免误点。
- **合并按 id 去重**：同一份文件导入两次是幂等的（「已导入 0 条，跳过 2 条重复」），
  这样用户可以放心地反复导入备份，不用先想清楚哪些已经导过。
- **结果按 endedAt 重排**：不假设导入文件里的顺序是对的。
- **如实报告**：`已导入 N 条，跳过 M 条重复，超出 200 条上限丢弃 K 条，现有 T 条`。

### 15.3 容错
| 情况 | 处理 |
| --- | --- |
| 文件不是 JSON | 提示「没有可用的练习记录」，不崩 |
| 兼容格式 | `{records:[...]}`（本应用导出）和裸数组 `[...]` 都吃 |
| 部分记录字段不全 | 逐条校验，坏数据跳过并告知条数（`parseImport` 返回 invalid） |
| 文件不是 UTF-8 | 解码出现替换字符时自动用 GBK 重试（Windows 记事本存的 JSON 可能是 GBK） |
| 连续选同一个文件 | 每次 change 后清空 input.value，否则第二次不触发 |
| 超出 200 条上限 | 裁掉最旧的，并在结果里说明丢了几条 |

### 15.4 测试与验证
- `tests/history.test.mjs` 新增 6 个用例：导入到空历史、**按 id 去重（同一文件导入两次不翻倍）**、
  按时间倒序重排、超上限裁剪并报告丢弃数、空输入、以及
  **导出 → 解析 → 合并的往返一致性**（逐字段比对 done/independent/hinted/errors/cpm/…/keyErrors）。
- 浏览器端到端（DataTransfer 模拟选文件，覆盖除系统弹框外的整条链路）：
  坏文件提示 ✓、确认行显示「找到 2 条记录（09-19 16:28 ～ 09-20 16:28）」✓、
  合并后 23 → 25 条且按时间倒序 ✓、同一文件再导入提示「已导入 0 条，跳过 2 条重复」✓、
  替换全部后只剩 1 条 ✓、取消后数量不变 ✓、全程零控制台报错 ✓。

### 15.5 发布包同步
代码改动后必须重建发布包（`npm run release`）并重跑 `npm run verify:file`，
否则用户拿到的还是旧版本。这一条也适用于以后任何改动。

## 16. 开始 / 暂停

### 16.1 触发改动的缺陷
需求来自「是不是应该加开始和暂停」这个问题，分析后发现一个实际问题：

> 没有暂停功能时，走开几分钟（接电话、看一眼别的窗口），
> 「卡住 3 秒自动闪键位」会在人不在的时候触发，于是**这道题被标记成「依赖提示」**。
> 回来之后它已经不算独立成绩了，但用户根本没看到那个提示。
> 切标签页、甚至人离开工位（不触发 visibilitychange）都会这样。

也就是说：暂停不只是体验问题，它把「提示统计」的口径从「大致可信」变成了「确实可信」。

### 16.2 设计：三态 + 自动暂停
`core/session-phase.ts`（纯函数）：

```
idle  --start-->  running  --pause-*-->  paused  --resume-->  running
  ^                                                              |
  └----------------------- restart ------------------------------┘
```

- **idle（未开始）**：页面加载后先停在这里。题面和键位图都显示出来（可以先切输入法、
  看键位图），但**不接收输入、不计时、不跑提示**，准备阶段的误触不会被记成错误。
- **running**：只有这个状态接收输入、跑计时和提示定时器。
- **paused**：三种来源（手动 `Esc`/按钮、切走标签页、长时间没输入）。

配套细节：
- 暂停时长用 `StatsTracker.shift()` 补进「发呆时间」：既不计入用时，
  也不会把恢复后第一次击键的反应时间算成「暂停了多久」。
- **离开较久（`pause-idle`）恢复时本题重新开始**：清空输入、清掉 `hintUsed`。
  理由见 16.1：那段时间的提示不能算用户看过。
  手动暂停和切标签页不重做（那是主动的、马上回来的），保持接着打的手感。
- 暂停时不跑提示定时器；未开始时也不跑。
- 暂停时仍然 `checkpoint()`，保证关掉页面也不丢这一轮。
- `空格` 在未开始/暂停时是「开始/继续」，在进行中才是「下一题/清空」。
  同一个键在不同状态下语义不同，但都符合直觉。

### 16.3 实现问题：副作用与状态赋值的顺序写反
`setPhase()` 最初的实现把副作用写在 `state.phase = next` **之前**，而
`startIdleWatch()` 内部要检查 `shouldTick(state.phase)`，它读到的还是旧值 `idle`，
于是定时器**根本没启动**：表现是「开始之后卡住提示不再触发」。

纯函数的 `reduce()` 单测全绿，因为转移表本身是对的；
`npm run verify:file` 也不会发现；只有浏览器端到端（等 3.4 秒看提示有没有闪）抓到了。
修法：**先把阶段落定，再跑副作用**，并在代码里留了注释说明原因。

### 16.4 测试与验证
- `tests/session-phase.test.mjs`（5 个用例）：完整生命周期、非法转移（未开始时暂停应无效）、
  只有 running 接收输入/跑计时、暂停原因与恢复行为、`resetsQuestionOnResume`
  只对 `idle` 为真。
- `tests/stats.test.mjs` 新增 2 个：`shift()` 把暂停时长记为发呆且不污染反应时间、
  传 0/负数时不变。
- 浏览器端到端实测：
  - 未开始状态按字母键：击键数 0、错误数 0（准备阶段误触不再污染成绩）✓
  - 空格开始后卡住 3.4 秒：提示照常触发（`hintStage=1`、闪烁 1 个键）✓
  - **暂停 5 秒并乱按键：提示完全不触发、`hintUsed` 保持 false、输入槽不变** ✓（这就是 16.1 的 bug）
  - 恢复后提示定时器重新开始计时（再等 3.3 秒正常触发）✓
  - 切走标签页自动暂停，切回来保持暂停等用户按空格 ✓
  - 自动暂停（阈值调成 1.2 秒）触发后恢复：本题被重做（`everFailed`/`hintUsed`/输入槽全部清空）✓
  - 暂停 4.2 秒后恢复，用时几乎不增加（`elapsedDelta = 0`）✓
  - 全程零控制台报错 ✓

## 17. 历史错误热力图

### 17.1 背景
之前热力图只能看**当前这一轮**。但单轮数据噪声很大：一轮里某个键按错 2 次，
可能只是手滑，也可能确实没记住，单轮分不出来。
**多轮累计之后才能看出「哪些键是真的没记牢」**，那才是下一步该重点练的。

### 17.2 实现
- `core/history.ts` 新增两个纯函数（可测）：
  - `aggregateKeyErrors(records, limit)` → `{ errors, total, rounds, keys, top }`，
    其中 `errors` 可以直接喂给键位图着色组件，`top` 是按次数排序的榜单
  - `aggregateCharErrors(records, limit)`，顺手把原先写在 store 里的错字聚合挪进 core，
    「易错复习」模式和「更多设置」里的设置面板都复用它
- 历史面板新增热力图区块：
  - **范围选择**：全部历史 / 最近 30 轮 / 最近 10 轮 / 选中的那一轮
  - **点表格任意一行 → 只看那一轮**（再点一次取消），选中行高亮
  - 键位图直接复用主界面组件（`KeyMap` + `HeatmapLegend`），所以配色、
    色阶、键位标注天然一致；外面包一层 `pointer-events: none` 表明这里只读
  - 数字随删除/导入/清空实时更新
- `HeatmapLegend` 加了 `scopeLabel`（默认「本轮」，历史里传「范围内」）。
  之前的历史区块会显示「本轮最多按错 N 次」，在多轮统计的语境下是错的。

### 17.3 测试与验证
- `tests/history.test.mjs` 新增 4 个用例：多轮累计与排序、`top` 数量限制与空输入、
  错字聚合与条数限制、**坏记录（缺 keyErrors / keyErrors 为 null）不能让统计崩掉**。
- 浏览器端到端（自己造两轮已知错误的数据来核对数字）：
  - 累计「7 次错误击键 · 3 个键 · 3 轮」，榜单 `q 4 · z 2 · m 1`，与手工汇总一致 ✓

  - 点第一行 → 变成「3 次 · 2 个键 · 第 3 轮」，榜单 `q 2 · m 1`，该行高亮 ✓
  - 再点一次取消选择，范围回到「全部历史」✓

  - 全程零控制台报错 ✓

## 18. 词库扩容（2500 → 12000）与取材范围

### 18.1 起因
用户反馈「词库数据有点少」。一查发现不只是数量问题，**质量也有两个洞**：

1. **专有名词混进来了**：第 12000 名之后开始出现「云中鹤 / 劳德诺 / 宋青书」（小说人名）、
   「孝感市 / 黄冈市」（地名）、「索马里」（音译）、「东交民巷 / 搜狗」（其他专名）。
2. **繁体重复项漏网**：我原来的「每个字都在常用字表里」能滤掉大部分繁体，
   但 `於/後` 这类字本身也在常用字表里，于是 `出於 / 落後 / 後人 / 大於` 都留在词库里。
   简体版本同时也在（`出于 / 落后 / 后人`），所以是纯重复。

### 18.2 三个新过滤器
| 过滤器 | 做法 | 效果 |
| --- | --- | --- |
| **词性** | jieba 词典自带词性，剔除 `nr/nrt/nrfg`(人名)、`ns`(地名)、`nt`(机构)、`nz`(专名) | 剔除 5615 条，人名地名全清 |
| **繁简** | opencc-js 转简，**判据是「简体对应词也存在」** | 剔除 122 条重复项 |
| **成语门槛** | `i`(成语) 单独放宽词频下限（200 → 30） | 成语池从 179 条涨到 2213 条 |

繁简去重的判据：不能简单要求「转换后是否变化」。
opencc 的台湾词库会把 `著` 转成 `着`，于是 `显著/著称/专著/土著` 这 4 个**正确的简体词**
会被误判成繁体。改成「简体对应词也存在才算重复」之后，这 4 个词正确保留。
这个不变量已经写成测试。

### 18.3 四字词配额
成语词频普遍只有几十，如果和普通词一起按词频排序，会全部落到 12000 名之外，
结果就是「词库看着大了，但一条成语都练不到」。所以给四字词留了 **1200 个名额**，
其余按词频填满，最后整体再按词频排（四字词自然落在末尾）。

### 18.4 取材范围
把词库直接扩到 1.2 万并沿用原来的名次加权，会让**三分之一的题目落在 5000 名之后**，
练起来大量是生僻词。所以加了单一设置项「词库范围」：

| 选项 | 内容 | 用途 |
| --- | --- | --- |
| 最常用 1000 词 | 前 1000 | 入门，全是高频词 |
| 最常用 3000 词（默认） | 前 3000 | 日常练习主力 |
| 最常用 6000 词 | 前 6000 | 扩大词汇面 |
| 全部 12000 词 | 全部 | 会遇到「郡县制」这种词 |
| 四字词 / 成语 | 1200 条四字词 | 节奏训练（**均匀随机**：这批词频都低，再按词频加权只会反复出前几条） |

### 18.5 测试与验证
- 新增 4 个数据质量用例 + 1 个范围用例：
  - 词库条数/字数分布/音节数=字数/逐字可编码
  - **专有名词回归**：把过滤前真实混进来的 10 个词（袁世凯/孝感市/云中鹤/索马里…）锁成断言
  - **简繁重复项不变量**：不存在 `t2s(word) !== word 且 t2s(word) 也在词库里` 的情况
  - 句子语料的汉字数 = 音节数
  - 范围生效：top1000 抽不到 3000 名之外的词；idiom 全是四字词且 100 次里 >50 个不同词
- 浏览器实测：范围下拉 5 个选项正确；四字词范围连抽 12 个全不重复
  （规章制度/得不偿失/意料之外/心惊胆战/随心所欲/百家争鸣…）；
  全部范围 + 均匀随机的字数分布 `{2:22, 3:2, 4:1}` 与词库比例（83%/7%/10%）吻合。
- 体积：数据从 241 KB / 51 KB gzip 涨到 **571 KB / 145 KB gzip**，
  主包 gzip 95 → 189 KB。**判断是不拆包**：本地运行（dev server / file://）加载是瞬间的，
  拆包只会让切模式多等一次异步加载；`vite.config.ts` 里写明了「如果以后要挂网站，
  把 words.ts 改成按需 import 就能压回约 70 KB」，而不是留个含糊的告警。

### 18.6 编码问题记录
PowerShell 重定向子进程输出时用的是**控制台编码**（本机 GBK）解码，
而 Node 写的是 UTF-8，于是生成脚本的中文报告全变乱码（甚至被当成二进制文件）。
解法：先 `[Console]::OutputEncoding = [System.Text.Encoding]::UTF8` 再重定向。
同类问题在本项目里出现过三次（前两次是 `Get-Content/Set-Content` 和测试文件乱码），
统一结论：**这个环境里涉及非 ASCII 内容的读写，要么用文件工具，要么先显式设置编码**。
